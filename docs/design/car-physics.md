# 車の挙動の仕様

状態: **第 5 版 (2026-09-25)**。数値は初期値で、ゲーム内の調整パネルで詰める前提 (15・16 節)。

第 5 版の理由 (ユーザーの決定): 第 4 版では、グリップ走行とドリフトの使い分け、ドリフトの出口の ERS ブーストを入れた。ユーザーの感想は「ドリフトの操作が直感的ではない。基本はブレーキで減速してコーナーを曲がる形にしたい」だった。ドリフト専用キーの案も示したが、ユーザーは **ドリフトをなくす** ことを選んだ。第 5 版では、ドリフト・ERS・ブーストと、それに関わる項目をすべて削除した。

第 4 版の「我慢」をなくすための考え方 (フルステアがちょうど限界、限界を超えたときの罰を軽く、壁に沿う補正、路面の罰を軽く) は残す。ユーザーが調整パネルで選んだ穏やかな操作の値 (`brakeDecel` 312.5、`steerRise` 3.5、`steerReturn` 6、`yawMaxLow` 2.0、カメラの回転の時定数 0.35 秒) を初期値にする。第 4 版の最初の案の値は `src/shared/carParams.ts` の `specCarParamValues` に残っている (表の「最初の案」の列)。

ルール面 (DRS の使用条件、ゴースト、コース復帰など) は `docs/design/game-design.md` を参照。

単位: 時間 = 秒、距離 = px、速度 = px/秒、加速度 = px/秒²、角度 = ラジアン (表では度も併記)。更新は固定タイムステップ `dt = 1/60 秒`。

## 0. 挙動の方針

**「ブレーキで減速して、グリップで曲がる」**。コーナーの手前でまっすぐブレーキを踏んで速度を落とし、ハンドルを切ってグリップで曲がり、立ち上がりでアクセルを踏む。差がつくのは、ブレーキを始める位置、ライン取り、アクセルを踏み始めるタイミング。

### 0.1 第 3 版の「我慢」の原因と対処 (第 4 版で決め、第 5 版でも残す)

第 3 版を試走したユーザーの評価は「気持ちよく曲がるのではなく、我慢して曲がる」だった。

| 原因 | 第 3 版の仕様 | 対処 |
| --- | --- | --- |
| 限界を超えると罰しかない | `steerDemand` 1.15 のため、キーボードでフルステアすると常に限界を約 15% 超える。曲がり方を `yawCmd / uReq` に削り (アンダーステア)、さらに最大 150 px/秒² 減速していた | フルステアがちょうど限界になるようにする (`steerDemand` 1.0)。限界を超えても曲がりを削りすぎず、減速も弱める (6 節) |
| 曲がれる速度が低く、アクセルを踏めない時間が長い | 横グリップ 562.5、加速 450 | 横グリップ 750、加速 500 (5・6 節)。コース幅も 60 → 80 px に広げる (game-design.md 11 章) |
| 狭い道幅と近い壁に対して速度が高く、リスクばかり大きい | コース幅 60 px、直線の芝生 40 px、壁の減速も大きい | コース幅 80 px、芝生 60 px 以上。壁は減速を軽くし、沿って滑るようにする。芝生・砂利の減速も弱める (8・9 節) |

### 0.2 気持ちよさの柱 (調整に迷ったらここに戻る)

1. **キーボードで扱いやすい、穏やかな操作** (ユーザーの決定): キーを押した瞬間に車の向きが変わり始めるが、ハンドルは約 0.3 秒かけて切れ、ブレーキも穏やかに長く効く。0/1 のキー入力でも車がぎくしゃくせず、切りすぎ・止まりすぎにならない。「即応」より「扱いやすさ」を優先する
2. **ブレーキで減速して曲がる**: コーナーの手前でしっかり減速すれば、あとはハンドルを切るだけで気持ちよく曲がれる。ブレーキの位置とラインで差がつく
3. **フルステアでちょうど限界**: キーボードで押しっぱなしにすると、グリップの限界ちょうどで曲がる。当て舵はいらない。グリップ走行中は、ハンドルを切っただけでは減速しない
4. **限界を超えたときの罰は軽く**: 速すぎてコーナーに入ったら少し外に膨らむが、急に止まったりはしない。芝生は減速するが即死ではなく、壁にかすっても沿って走り続けられる
5. **強い衝突だけがスピンになる**: 壁への強い衝突と車同士の強い接触でだけスピンする (7 節)

### 0.3 実装の前提

- 計算は単純な式にし、全パラメータを 1 つの設定オブジェクト `CarParams` にまとめる (15 節)。M4 でホストの Web Worker と共有するため、DOM に依存させない (`src/shared/`)
- 車は `Controls` だけを見て動く (game-design.md 5.3 節)
- 調整パネルで値を実行中に変えられるように、`CarParams` から毎フレーム値を読む。値から前もって計算した値をキャッシュしない (16 節)

## 2. 座標系・状態・描画

### 2.1 座標系

- 物理・判定・コースデータの座標は **画面 px (800×600 基準)** で持つ。1 ドット = 2 px
- x は右向き、y は下向き (Canvas と同じ)。ワールドの上 = 北
- **向き θ: 0 = 北 (上) 向き、時計回りが正**。前方ベクトル `f = (sin θ, −cos θ)`、右方ベクトル `r = (cos θ, sin θ)`
- 車のスプライトは北向きに描かれているので、描画時の角度の補正は要らない
- `Math.atan2(dy, dx)` で求めた角度 `a` を θ に変換するときは `θ = a + π/2`

### 2.2 描画

描画の方式 (ワールド層の拡大、カメラの回転) は style-guide.md §1 と game-design.md 10.5 節に従う。物理は丸めない (丸めるのは描画だけ)。

### 2.3 車の状態

| 変数 | 意味 |
| --- | --- |
| `x, y` | 車の中心の位置 (px) |
| `θ` | 車体の向き |
| `sF`, `sR` | 車体から見た前方向・右方向の速度。速度ベクトル `v = f × sF + r × sR`。`sR` は接触・壁で生じる横方向の速度の残りで、通常は 0 |
| `steer` | 実際のステア量 −1〜1 (入力を平滑化したもの) |
| `fSlip`, `fDrs` | スリップストリーム・DRS の効き 0〜1 |
| `wear`, `compound` | タイヤの摩耗 0〜1 と種類 |
| `spinTimer` | スピンの残り時間 |

入力 `Controls`: `throttle` 0〜1、`brake` 0〜1、`steerInput` −1〜1、`steerIsAnalog`、`drsPressed`、`resetPressed`。キーボード (←→ ハンドル、Z アクセル、X ブレーキ。game-design.md 5.1 節) では、throttle・brake は 0 か 1、steerInput は −1 / 0 / 1。

## 3. 1 フレームの更新順序

1. `Controls` を読む (スピン中・自動運転中・復帰中は無視)。アクセルとブレーキを同時に押したらブレーキを優先し、アクセルは 0 とする
2. ステアの平滑化 (4 節)
3. 車輪 4 点の路面を調べ、グリップ・ブレーキ・加速の倍率と追加減速を求める (8 節)
4. タイヤ・DRS などを含めたグリップ倍率 `G` と最高速 `Veff` を求める (5・10〜12 節)
5. 旋回: 向き θ を更新する (6 節)。スピン中は 7 節
6. 前後方向: `sF` を更新する (5 節)
7. 横方向の残り速度 `sR` を減衰させる (6.4 節)
8. 位置を更新する: `(x, y) += v × dt`
9. 壁との衝突 (9.2 節)
10. 全車の移動後に、車同士の衝突 (9.1 節)
11. スリップストリーム・DRS の状態、摩耗を更新する (10〜12 節)
12. 演出の判定 (スキール音、タイヤ痕、火花。14 節)

## 4. ステア入力

### 4.1 キーボード・十字キー (`steerIsAnalog = false`)

0/1 の入力で一瞬で切り替わると唐突なので、`steer` を目標値 `steerInput` へ一定の速さで近づける。キーボードで扱いやすい **穏やかな速さ** にする (ユーザーの調整)。

| 状況 | 変化の速さ (初期値) | 所要時間 | 最初の案 | 調整の幅 |
| --- | --- | --- | --- | --- |
| 目標に向かって大きくなる (0 → ±1) | `steerRise` 3.5 /秒 | 0 → 1 に約 0.29 秒 | 15 (0.07 秒) | 2〜25 |
| 0 に戻る (キーを離した) | `steerReturn` 6 /秒 | 1 → 0 に約 0.17 秒 | 20 (0.05 秒) | 3〜30 |
| 逆方向に切り返す | 0 までは `steerReturn`、そこから `steerRise` | ±1 → ∓1 に約 0.45 秒 | 約 0.12 秒 | |

キーを軽く叩くと浅く切れるので、キーボードでも切る量を調整できる。

### 4.2 ゲームパッドのアナログスティック (`steerIsAnalog = true`、M3)

```
x = axes[0]
|x| < 0.15 なら 0
それ以外: n = (|x| − 0.15) / 0.85
          steerInput = sign(x) × n^1.5
steer = steerInput          // 平滑化しない
```

- トリガーはデッドゾーン 0.05 を除いて 0〜1 に広げ直し、`throttle` / `brake` に使う
- キーボードと同時に使った場合は、ステアは絶対値が大きい方を採用する。採用した方がキーボード・十字キーなら 4.1 節の平滑化を通す
- CPU の AI もアナログ扱いで、ステア量を直接出す

## 5. 前後方向 (加速・最高速・ブレーキ・惰性・後退)

### 5.1 パラメータ

| 名前 | 初期値 | 最初の案 | 第 3 版 | 調整の幅 | 意味 |
| --- | --- | --- | --- | --- | --- |
| `vBase` | 525 | 525 | 525 | 480〜575 | 基本の最高速 (表示 315 km/h) |
| `accel0` | 500 | 500 | 450 | 450〜600 | 停止時の加速度 |
| `brakeDecel` | **312.5** (ユーザーの値) | 650 | 562.5 | 250〜800 | 最大ブレーキの減速度 (グリップ 1.0 のとき) |
| `coastBase` / `coastDrag` | 37.5 / 87.5 | 同じ | 同じ | | アクセルを離したときの減速 (定数部分 / 最高速での空気抵抗分) |
| `reverseAccel` / `reverseMax` / `reverseDelay` | 187.5 / 112.5 / 0.3 秒 | 同じ | 同じ | | 後退 |

### 5.2 最高速

```
Veff = vBase × (1 + min(bonusCap, 0.08 × fSlip + 0.10 × fDrs))
```

- 上乗せの合計には上限 `bonusCap` 0.25 を設ける (スリップストリームと DRS を重ねても +18% なので、今は上限に届かない。将来の上乗せに備えた値)
- ピットレーン・自動運転中は `min(Veff, 225)`
- タイヤの種類・摩耗は最高速に影響しない

### 5.3 加速度

```
s = max(sF, 0)
aEngine  = throttle × accel0 × surfaceAccel × (1 − (s / Veff)²)
aBrake   = brake × brakeDecel × Gbrake
aCoast   = (1 − throttle) × (coastBase + coastDrag × (s / vBase)²)
aScrub   = 限界超えの減速 (6.3 節)
aSurface = コース外の追加減速 (8 節)

sF += (aEngine − aBrake − aCoast − aScrub − aSurface) × dt
```

- `s > Veff` のとき (スリップストリーム・DRS が切れた直後) は `aEngine` が負になり、自然に減速する
- 減速の項で `sF` が 0 をまたいだら 0 で止める
- `Gbrake` = タイヤのグリップ × 路面のブレーキ倍率

### 5.4 後退

`sF ≤ 6` の状態でブレーキだけを 0.3 秒押し続けると後退モードに入る。後退中はブレーキ入力で後ろに加速し (最大 112.5 px/秒)、アクセルは後退を止めるブレーキとして働く。

### 5.5 目安の数値 (グリップ 1.0)

| 項目 | 初期値 (312.5) | 最初の案 (650) | 第 3 版 |
| --- | --- | --- | --- |
| 0 → 500 px/秒 | 約 1.95 秒・約 655 px | 同じ | 2.2 秒・730 px |
| 最高速 525 → 400 のブレーキ | 約 0.30 秒・約 138 px | 0.17 秒・77 px | |
| 最高速 525 → 300 のブレーキ | 約 0.56 秒・約 228 px | 0.30 秒・124 px | |
| 最高速 525 → 200 のブレーキ | 約 0.83 秒・約 295 px | 0.44 秒・160 px | 0.50 秒・180 px |

ブレーキは第 3 版より長く、穏やかに効く。ブレーキ距離が長いぶん、ブレーキを始める位置の差 (0.1 秒 = 最高速で 52 px) がブレーキ距離に占める割合は小さく、ブレーキの位置の失敗が許されやすい。

## 6. 旋回とグリップ限界

### 6.1 パラメータ

| 名前 | 初期値 | 最初の案 | 第 3 版 | 調整の幅 | 意味 |
| --- | --- | --- | --- | --- | --- |
| `latGrip` | 750 | 750 | 562.5 | 650〜900 | 横方向に出せる最大の加速度 (グリップ倍率 1.0) |
| `yawMaxLow` | **2.0 rad/秒 (115°/秒)** (ユーザーの値) | 3.6 | 3.0 | 1.5〜4.5 | 低速での最大旋回速度 |
| `yawRampSpeed` | 40 | 40 | 50 | 25〜60 | これより遅いと旋回速度が速度に比例して小さくなる |
| `steerDemand` | **1.00** | 1.00 | 1.15 | 0.95〜1.10 | フルステアで要求する横加速度 = `latGrip × steerDemand` |
| `understeerSoftness` | 0.5 | 0.5 | (1.0 相当) | 0〜1 | 限界を超えたときに曲がりを削る強さ (6.2 節)。1 で第 3 版と同じ、0 で削らない |
| `scrubRate` / `scrubMax` | 0.25 / 80 | 同じ | 0.5 / 150 | 0〜0.5 / 0〜150 | 限界超えの減速 |
| `brakeGripLoss` | 0.2 | 0.2 | 0.25 | 0〜0.3 | ブレーキ中の横グリップの低下 (フルブレーキで 20%) |
| `lateralDecay` | 1,200 | 1,200 | 750 | 800〜2,000 | 横方向の速度 `sR` を 0 に戻す速さ |

### 6.2 旋回の計算

```
s = |sF|
yawLimit = min(yawMaxLow × min(1, s / yawRampSpeed), latGrip × steerDemand / s)   // s = 0 なら 0
yawCmd   = steer × yawLimit × sign(sF)

aLatMax  = latGrip × G
aReq     = s × |yawCmd|
uReq     = aReq / aLatMax                    // グリップ使用率

yaw = uReq > 1 ? yawCmd / uReq^understeerSoftness : yawCmd
θ += yaw × dt
```

`G` (横グリップの倍率) = タイヤ (10 節) × 路面 (8 節) × `(1 − brakeGripLoss × brake)` × DRS が開いていれば 0.9。

考え方:

- `steerDemand` が 1.0 なので、グリップ 1.0 の路面でフルステアすると、`uReq` がちょうど 1 になる。**キーボードで押しっぱなしにするのが最も速い曲がり方** になり、当て舵はいらない。ソフトタイヤ (1.08) なら `uReq` は約 0.93 で、限界の少し手前になる
- ただしこれは `latGrip / yawMaxLow` 以上の速度の場合 (初期値では 375 px/秒 以上、最初の案では約 208 px/秒 以上)。それより遅いと旋回速度の上限 `yawMaxLow` で決まり、グリップを使い切る前に曲がりが頭打ちになる。初期値では低速のヘアピンで「曲がりが遅い」と感じる可能性がある (18 節)
- 限界を超えるのは、グリップが落ちたとき (芝生・縁石、ブレーキを踏みながら曲がったとき、摩耗したタイヤ) と、速すぎてコーナーに入ったとき。そのときも `understeerSoftness` 0.5 のため、第 3 版より曲がりを削る量が少ない。例: `uReq` 1.2 なら第 3 版は 83% まで曲がりを削ったが、第 4 版以降は 91% まで曲がる
- ブレーキを踏みながら曲がると横グリップが 20% 落ちるので、「まっすぐブレーキ → 離して曲がる」ほうが速い。ブレーキを残しながら曲がり始める (トレイルブレーキ) こともできるが、踏みすぎると膨らむ

### 6.3 限界超えの減速

```
aScrub = uReq > 1 ? min(scrubMax, scrubRate × (aReq − aLatMax)) : 0
```

限界内 (`uReq ≤ 1`) では減速しない (「ハンドルを切っても減速が少ない」)。

### 6.4 横方向の残り速度

接触・壁で生じた横方向の速度 `sR` は、毎フレーム 0 に向かって減らす。

```
sR を 0 に向かって min(|sR|, lateralDecay × 路面のグリップ倍率 × dt) だけ減らす
```

通常の走行では `sR = 0` のまま (向きを変えると、速度の向きも一緒に変わる)。

### 6.5 見た目の滑り角

限界付近では、車の絵だけを少し内側に向けて「タイヤが粘っている」感じを出す。当たり判定と進行方向は変えない。

```
描画用の向き = θ + sign(yaw) × clamp((uReq − 0.9) × 25°, 0°, 6°)
```

### 6.6 コーナーの限界速度の目安

`v = √(latGrip × G × R)` (R はレーシングラインの半径)。

| R (px) | ハード新品 (0.96) | 基準 (1.00) | ソフト新品 (1.08) |
| --- | --- | --- | --- |
| 100 | 268 | 274 | 285 |
| 150 | 329 | 335 | 349 |
| 200 | 379 | 387 | 402 |
| 250 | 424 | 433 | 450 |
| 300 | 465 | 474 | 493 |
| 368 以上 | 全開 (525) | 全開 | 全開 |

低速側の旋回の限界: 40〜375 px/秒 では `yawMaxLow` の 2.0 rad/秒 で決まる (最初の案では 40〜208 px/秒、3.6 rad/秒)。フルステアでの最小半径は、速度 ÷ 2.0 (150 px/秒 で 75 px、300 px/秒 で 150 px)。上の表のうち、半径 R が速度 ÷ 2.0 より小さいコーナーは、この表の速度では曲がれない (実際の速度は、R × 2.0 と表の値の小さいほう)。

## 7. スピン

強い衝突でだけスピンする。第 4 版にあった「ドリフトのやりすぎ」によるスピンはない。

| 原因 | 条件 | スピンの時間 |
| --- | --- | --- |
| 壁 | 衝撃 J ≥ `spinImpulseWall` (500 px/秒) かつ 壁への進入角が `spinWallMinAngle` (60°) 以上 (9.2 節) | 短い (`spinTimeLight` 0.6 秒) |
| 車同士の接触 | 9.1 節 (J ≥ 375) | 長い (`spinTimeContact` 1.0 秒。体当たりを損にするため) |

| 項目 | 短いスピン (壁) | 長いスピン (接触) |
| --- | --- | --- |
| 時間 (操作を受け付けない) | 0.6 秒 | 1.0 秒 |
| 回転 | 開始時 6 rad/秒 から 0 まで直線的に減らす (約 100°)。回転の向きは衝撃の向きから決める | 開始時 8 rad/秒 から 0 まで (約 230°) |
| 減速 | 450 px/秒² | 625 px/秒² |
| 終了後 | その時点の向き・速度のまま操作が戻る | 同じ |

- スピン中は速度ベクトルを向きと切り離して扱い (滑りながら回る)、終了時に `sF = v · f`、`sR = v · r` で戻す
- 逆向きで止まったら逆走警告、止まっていればコース復帰が使える (game-design.md 7.11 節)
- 条件と時間は game-engineer の実装に合わせて確定する (18 節)

## 8. 路面

車輪 4 点それぞれの路面を調べ、グリップ・ブレーキ・加速は 4 点の平均、追加減速は 4 点の合計 (各 1/4) で決める。

| 路面 | グリップ | ブレーキ | 加速 | 速度の上限 | 上限を超えているときの追加減速 | 第 3 版からの変更 |
| --- | --- | --- | --- | --- | --- | --- |
| アスファルト (白線を含む) | 1.00 | 1.00 | 1.00 | なし | 0 | |
| 縁石 | 0.97 | 0.95 | 1.00 | なし | 0 | 0.92 → 0.97。乗っても損がほとんどない |
| ピットレーン | 1.00 | 1.00 | 1.00 | なし | 0 | |
| 芝生 | 0.70 | 0.55 | 0.75 | 260 px/秒 | 400 px/秒² | 0.60 / 225 / 437.5 から緩めた |
| 砂利 | 0.50 | 0.45 | 0.60 | 180 px/秒 | 500 px/秒² | 0.45 / 137.5 / 687.5 から緩めた |

目安 (4 輪とも、500 px/秒 で突っ込んだとき):

| 路面 | アクセルを離した場合 | アクセルを踏んだまま |
| --- | --- | --- |
| 芝生 (→ 260 px/秒) | 約 0.5 秒 | 約 1.2 秒 |
| 砂利 (→ 180 px/秒) | 約 0.6 秒 | 約 0.9 秒 |

- 方針: **芝生は「減速するが即死ではない」**。少しはみ出してもアクセルを戻さずにコースに戻れる。砂利は、ブレーキの大失敗 (ヘアピン・1 コーナーの突っ込みすぎ) を受け止める場所で、芝生より強く減速する
- コース外を通ると得をする場所 (ショートカット) は、コースデータで砂利にするか、チェックポイントのゲートで無効にする。ヘアピン・S 字の内側は、縁石の先を砂利にする (game-design.md 11.1 節)
- 壁 (タイヤバリア) は路面ではなく衝突物として扱う (9.2 節)

## 9. 接触

### 9.1 車同士

```
J  = max(0, (vA − vB) · n)
押し戻し: 1 人用は両方を depth / 2 ずつ、マルチは自車だけ depth
反発:     vA −= (1 + e) / 2 × J × n、vB += (1 + e) / 2 × J × n   (e = 0.2)
当てた側: cA − cB > 25 なら A、cB − cA > 25 なら B、差が 25 以内なら両方
当てた側の速度ベクトル ×= (1 − min(0.30, J / 1000))
当てられた側の sF が接触前より大きくなったら接触前の値に戻す
J ≥ 375: 当てた側はスピン。当てられた側が横から (|n · r| > 0.7) 当てられたなら、当てられた側もスピン
```

- 判定は当たり判定の長方形 (18 × 38 px、向き付き) 同士の分離軸判定 (SAT)。ゴーストの組み合わせ (game-design.md 7.10 節) は判定しない
- 同じ 2 台の組み合わせでは、最後の衝撃から 0.2 秒以内の衝撃は適用しない (押し戻しだけ行う)
- 速度ベクトルを変えたあとは、`sF`・`sR` を新しい速度ベクトルから計算し直す
- マルチ: 自車に適用した `J` と `n` を `collision` メッセージで送る。当てた側の判定は両者の速度から同じ式で決まるので、両クライアントで一致する

| J (px/秒) | 状況の例 | 結果 |
| --- | --- | --- |
| 〜50 | 並走中に軽くこする | 押し戻しのみ。火花なし |
| 50〜187.5 | ブレーキングで軽く追突 | 火花が出て、当てた側が 5〜19% 減速 |
| 187.5〜375 | 大きく追突、横からぶつける | 火花、画面揺れ、当てた側が 19〜30% 減速 |
| 375〜 | ブレーキを忘れて突っ込む | 当てた側がスピン (横から当てたなら両方) |

### 9.2 壁 (タイヤバリア)

**方針: 罰を軽くし、壁に沿って滑るようにする**。触れただけで止まったり、弾かれて逆を向いたりしない。

```
J  = max(0, −v · n)                        // n は壁から車に向かう法線
押し戻し: めり込み分を n 方向へ
法線方向の速度: vN ← −wallRestitution × vN               (0.3。少し弾かれる)
接線方向の速度: vT ← vT × (1 − min(wallTangentLossMax, J / wallTangentLossDiv))   (最大 0.35、J / 1000)
向きの補正: 壁への進入角が wallAlignMaxAngle (35°) 未満なら、車体の向きを壁の接線方向へ
            最大 wallAlignRate (6 rad/秒) で寄せる (かすったら壁に沿って走り続けられる)
J ≥ spinImpulseWall (500) かつ 進入角 ≥ spinWallMinAngle (60°) → 短いスピン (7 節)
```

- 目安: 450 px/秒 で 20° の角度でかすると、J ≈ 154。速度は約 15% 落ちるが、向きが壁に沿って直るので、そのまま走れる。90° で正面からぶつかるとスピンする
- 演出 (火花・画面揺れ・音) は、車同士と同じく J が 50 以上で火花、187.5 以上で画面揺れ

## 10. タイヤ (種類と摩耗)

### 10.1 グリップ

```
タイヤのグリップ = compoundGrip × wearFactor(wear)
compoundGrip: ソフト 1.08、ハード 0.96
wearFactor(w) = 1 − 0.08 × w               (w < 0.7)
              = 0.944 − 0.5 × (w − 0.7)     (w ≥ 0.7、崖)
w は 1.0 で止める (wearFactor の最小値 0.794)
```

タイヤのグリップは、横グリップ `G` とブレーキ `Gbrake` の両方にかかる。最高速・加速には影響しない。

| 状態 | ソフト | ハード |
| --- | --- | --- |
| 新品 (w = 0) | 1.080 | 0.960 |
| w = 0.35 | 1.050 | 0.933 |
| w = 0.70 (崖の手前) | 1.020 | 0.906 |
| w = 0.85 | 0.939 | 0.834 |
| w = 1.00 | 0.858 | 0.762 |

HUD の摩耗バー (style-guide.md §6) は残り = `1 − w` を表示する。残り 30% (w = 0.7) で赤になり、崖の始まりと一致する。

### 10.2 摩耗

```
L = max(min(uReq, 1.5), 0.8 × brake)                // タイヤへの負荷 (限界超えも数える)
wear += k × (s / vBase) × (0.4 + 0.6 × L) × dt

k: ソフト 0.0155 /秒、ハード 0.0064 /秒
```

- 速度に比例して減るので、止まっていれば減らない
- 限界を超えてこする (`uReq > 1`) ほど早く減る。丁寧に走るほど長持ちする
- 目標: 普通に走って 1 周でソフト 0.30〜0.38、ハード 0.12〜0.16。実装後にデバッグ表示で 1 周の摩耗を測り、`k` を調整する (コース 1 は 1 周 17,546 px)
- タイムアタックでは摩耗しない (`wear` = 0 に固定)。予選・決勝では摩耗する

## 11. スリップストリーム

条件 (前にいる車 L と自車 M について、毎フレーム全車を調べる。決勝のみ):

```
L の後端 = L の位置 − L の f × 19
d = |M の位置 − L の後端|
角度1 = (M の位置 − L の位置) の向き と (−L の f) のなす角
角度2 = M の θ と L の θ の差

有効: d ≤ 150 かつ 角度1 ≤ 20° かつ 角度2 ≤ 30° かつ M の sF ≥ 250 かつ L とゴーストの関係でない
```

- 効き `fSlip`: 有効な間は +2.0 /秒 で上げ (0 → 1 に 0.5 秒)、無効になったら −2.0 /秒 で下げる
- 効果: 最高速 +8% (5.2 節)。加速の式が `Veff` を使うので、高速域の加速も良くなる
- 複数の車が条件を満たしても、効果は 1 台分
- HUD にメーターは出さない。風の線のエフェクトと `slipstream-wind-loop` (音量 = `fSlip`) で伝える
- 予選・タイムアタックでは効かない (全車ゴーストで重なって走ることがあり、不自然なため)

## 12. DRS

- 使用条件は game-design.md 7.6 節。自車の状態として `drsAvailable` (この周の区間で使える)、`drsOpen` を持つ
- 開く: `drsAvailable` かつ DRS 区間内で `drsPressed`
- 閉じる: ブレーキ入力 (`brake > 0`)、区間の終了ラインの通過、スピン、ピットの自動運転
- 効き `fDrs`: 開くと +5.0 /秒 (0.2 秒で 1)、閉じると −5.0 /秒
- 効果: 最高速 +10% (5.2 節)。開いている間は横グリップ ×0.9 (6.2 節)。ブレーキで自動的に閉じるので、開いたままコーナーに入ることは通常ない

## 13. ピットレーンの自動運転

- ピット入口ラインを越えたら `Controls` を無視し、ピットレーンの経路を CPU と同じ pure pursuit で追う
- 速度制限は 225 px/秒。入口で 225 を超えていれば `brakeDecel` で自動的に減速する
- ボックス手前で停止位置に合わせて減速し、2.0 秒停止したあと、出口まで 225 px/秒 で走る
- 自動運転中も位置・向き・速度は通常の物理で更新する (ワープしない)。路面判定・壁判定は行わない

## 16. 調整の方針と確認方法

### 16.1 調整パネルとの関係

- 調整パネル (実装済み、開発時だけ。F4 で開く。操作は game-design.md 12 章 M1) は、`CarParams` の値を実行中に書き換える。車は毎フレーム `CarParams` を読むので、書き換えた次のフレームから効く
- 調整パネルで 1 つでも初期値から変えている間は、自己ベスト・ゴーストを **保存しない** (違う物理でのタイムが記録に混ざらないように)。タイムのパネルに `TUNED` と出す
- 気に入った値は、調整パネルから JSON で書き出して `carParams.ts` の初期値に反映し、`physicsVersion` を上げる

### 16.2 優先順位 (上ほど先に合わせる)

1. **曲がる感触**: キーボードで高速コーナー (コース 1 の T4) とヘアピン (T7) を走る。「押した瞬間に曲がり始める」「急すぎない」「押しっぱなしで曲がれる」「減速を感じない」か。ユーザーが選んだ穏やかな値 (`steerRise` 3.5、`yawMaxLow` 2.0) を基準にする。ヘアピンで曲がりが遅すぎると感じたら `yawMaxLow` を少し上げる (18 節)
2. **ブレーキ**: 最高速から T1・T8 までのブレーキ (525 → 400 px/秒 に約 138 px・0.30 秒。DRS を使った T8 ではもう少し長い) が短すぎ・長すぎでないか。`brakeDecel` で調整する
3. **限界を超えたとき**: 速すぎて入ったときに「少し膨らむ」程度で済むか。罰が重く感じたら `understeerSoftness` と `scrubRate` を下げる
4. **ラップタイム**: game-design.md 11 章の目安 (sim で測り直す) に近いか。コースの形は変えず、車の性能は 1〜3 で決めた値を動かさない
5. **コース外・壁**: 芝生に出たときの損がミス 1 回につき 0.3〜1.0 秒、壁にかすったときの損が 0.3 秒程度か
6. **追い抜き・タイヤ** (M2・M3): DRS 区間で 0.5 秒差から並べるか、戦略の差が 1 秒以内か

### 16.3 確認方法

- F3 のデバッグ表示に、`s`、`uReq`、`G`、路面、`fSlip`、`fDrs`、`wear` を出す
- `scripts/sim-lap.mjs` で、AI のラップ・区間タイム (アナログ操作とキーボード相当の 0/1 入力)、5.5 節・8 節の目安の数値、壁・スピンの条件を確かめる
