# 車の挙動の仕様

状態: **第 2 版 (2026-09-25)**。数値は初期値で、テストプレイで調整する前提。調整の方針は各節に書く。
第 2 版では、ユーザー確認済みの車の大きさ (画面 20×40 px) に合わせ、px を含む値 (距離・速度・加速度) をすべて初版の 1.25 倍にした。時間・角度・倍率は変えていないので、ラップタイムなどの時間は初版と同じになる。
ルール面 (DRS の使用条件、ゴースト、コース復帰など) は `docs/design/game-design.md` を参照。

単位: 時間 = 秒、距離 = px、速度 = px/秒、加速度 = px/秒²、角度 = ラジアン (表では度も併記)。更新は固定タイムステップ `dt = 1/60 秒`。

## 0. 挙動の方針

- **アーケード寄り、グリップ重視**。車は基本的に向いている方向に進み、横滑り (ドリフト) で曲がることはない
- 差がつくのは **ブレーキポイント** と **ライン取り**。速すぎると曲がりきれずに外にふくらむ (アンダーステア)
- 限界に近づくとスキール音、限界を超えるとタイヤ痕とスピードの損失で知らせる
- 計算は単純な式にし、全パラメータを 1 つの設定オブジェクト (`CarParams`) にまとめる。M4 でサーバーと共有するため DOM に依存させない

## 1. 車の寸法

style-guide.md §2 でユーザー確認済みの大きさ (車体 10×20 ドット、1 ドット = 2 px) に合わせる。

| 項目 | 値 | 備考 |
| --- | --- | --- |
| 車体 (スプライトの中身) | 20 × 40 px (幅 × 長さ) = 10 × 20 ドット | スプライトファイルは 24×24 ドット、回転中心はファイル中心 (12, 12) = 車体の中心 |
| 当たり判定 (向き付きの長方形) | 18 × 38 px | 車体より 1 px ずつ内側 |
| 車輪の位置 (路面判定用) | 中心から 前 13 px / 後 12 px、左右 ±8 px の 4 点 | style-guide.md の設計図のタイヤ位置 (前輪 行 2〜4、後輪 行 14〜17、列 0〜1 / 8〜9) の中心 |
| コース幅との関係 | 標準コース幅 60 px = 車 3 台分 | game-design.md 11.1 節 |

最高速 525 px/秒では 1 秒に車 13 台分進む (実際の F1 とほぼ同じ比率)。
寸法を変える場合は、px を含む値 (コース幅、グリッド間隔、スリップストリームの距離、接触の閾値、コーナー半径、カメラの先読みなど) をすべて同じ比率で変える。そうすれば時間の値 (ラップタイム、ブレーキにかかる秒数など) は変わらない。

## 2. 座標系・状態・描画

### 2.1 座標系

- 物理・判定・コースデータの座標は **画面 px (800×600 基準)** で持つ。1 ドット = 2 px
- x は右向き、y は下向き (Canvas と同じ)。画面の上 = 北
- **向き θ: 0 = 北 (上) 向き、時計回りが正**。前方ベクトル `f = (sin θ, −cos θ)`、右方ベクトル `r = (cos θ, sin θ)`
- 車のスプライトは北向きに描かれている (style-guide.md §2) ので、**描画時の角度の補正は要らない** (`ctx.rotate(θ)` をそのまま使う)
- `Math.atan2(dy, dx)` (0 = 東向き、時計回りが正) で求めた角度 `a` を θ に変換するときは `θ = a + π/2`。逆は `a = θ − π/2`

### 2.2 描画 (style-guide.md §1)

- ワールド (コース・車・エフェクト) は **400×300 のオフスクリーン Canvas に 1 ドット = 1 px で描き**、`imageSmoothingEnabled = false` で 2 倍に拡大して 800×600 に転送する
- 物理の座標 (px) からオフスクリーンの座標 (ドット) への変換: `dot = round((world − camera) / 2) + (200, 150)`。カメラ位置と車の描画位置はドット単位に丸める
- 車は 24×24 ドットのスプライトを、オフスクリーン上で車の中心を軸に `ctx.rotate(θ)` して描く
- 物理は丸めない (丸めるのは描画だけ)
- HUD・名前タグは 800×600 に直接描く (2 px 単位)

### 2.3 車の状態

| 変数 | 意味 |
| --- | --- |
| `x, y` | 車の中心の位置 (px) |
| `θ` | 向き |
| `sF` | 前方向の速度 (負なら後退) |
| `sR` | 横方向の速度 (接触などで生じる残り。通常は 0) |
| `steer` | 実際のステア量 -1〜1 (入力を滑らかにしたもの) |
| `fSlip` | スリップストリームの効き 0〜1 |
| `fDrs` | DRS の効き 0〜1 |
| `wear` | タイヤの摩耗 0〜1 |
| `compound` | タイヤの種類 (soft / hard) |
| `spinTimer` | スピンの残り時間 |

速度ベクトルは `v = f × sF + r × sR`。

入力 `Controls`: `throttle` 0〜1、`brake` 0〜1、`steerInput` -1〜1、`steerIsAnalog` (アナログ入力なら true)、`drsPressed`、`resetPressed`。キーボードでは throttle・brake・steerInput は 0 か 1 (steerInput は -1 / 0 / 1)。

## 3. 1 フレームの更新順序

1. `Controls` を読む (スピン中・自動運転中・復帰中は無視)
2. ステアの平滑化 (4 節)
3. 車輪 4 点の路面を調べ、グリップ倍率・追加減速を求める (7 節)
4. タイヤ・DRS などを含めたグリップ倍率 `G` と最高速 `Veff` を求める (5・10・11・12 節)
5. 旋回: 向き θ を更新する (6 節)
6. 前後方向: `sF` を更新する (5 節)
7. 横方向の残り速度 `sR` を減衰させる (6.4 節)
8. 位置を更新する: `(x, y) += v × dt`
9. 壁との衝突 (9.2 節)
10. 全車の移動後に、車同士の衝突 (9.1 節)
11. スリップストリーム・DRS の状態、摩耗を更新する (11・12・10 節)
12. 演出の判定 (スキール音、タイヤ痕、火花) (8 節)

## 4. ステア入力 (キーボードとゲームパッド)

### 4.1 キーボード・十字キー (`steerIsAnalog = false`)

0/1 の入力をそのまま使うとカクつくので、`steer` を目標値 `steerInput` へ一定の速さで近づける。

| 状況 | 変化の速さ |
| --- | --- |
| 目標に向かって大きくなる (0 → ±1) | 6.0 /秒 (0 → 1 まで 0.17 秒) |
| 0 に戻る (キーを離した) | 10.0 /秒 (1 → 0 まで 0.10 秒) |
| 逆方向に切り返す | まず 10.0 /秒 で 0 まで戻し、その後 6.0 /秒 で逆へ |

### 4.2 ゲームパッドのアナログスティック (`steerIsAnalog = true`)

```
x = axes[0]
|x| < 0.15 なら 0
それ以外: n = (|x| − 0.15) / 0.85            // デッドゾーンの外を 0〜1 に広げ直す
          steerInput = sign(x) × n^1.5       // 中央付近を穏やかにする応答カーブ
steer = steerInput                            // 平滑化しない (スティック自体がなめらかなため)
```

- ステア量は中間の値を取れるので、`6.2 節` の要求横加速度が `latGrip` を下回るように浅く切れば、スキール音を鳴らさずに限界の手前で曲がれる
- アクセル・ブレーキのトリガーはデッドゾーン 0.05 を除いて 0〜1 に広げ直し、そのまま `throttle` / `brake` に使う (応答カーブなし)
- キーボードとゲームパッドを同時に使った場合 (game-design.md 5.2 節): ステアは絶対値が大きい方を採用する。採用した方が十字キー・キーボードなら 4.1 節の平滑化を通す
- CPU の AI もアナログ扱い (`steerIsAnalog = true`) で、ステア量を直接出す

## 5. 前後方向 (加速・最高速・ブレーキ・惰性・後退)

### 5.1 パラメータ

| 名前 | 値 | 意味 |
| --- | --- | --- |
| `vBase` | 525 px/秒 | 基本の最高速 (表示 315 km/h) |
| `accel0` | 450 px/秒² | 停止時の加速度 |
| `brakeDecel` | 562.5 px/秒² | 最大ブレーキの減速度 (グリップ倍率 1.0 のとき) |
| `coastBase` | 37.5 px/秒² | アクセルを離したときの減速 (定数部分) |
| `coastDrag` | 87.5 px/秒² | アクセルを離したときの減速 (最高速での空気抵抗分) |
| `reverseAccel` | 187.5 px/秒² | 後退の加速度 |
| `reverseMax` | 112.5 px/秒 | 後退の最高速 |
| `reverseDelay` | 0.3 秒 | 停止中にブレーキを押し続けてから後退に入るまで |

### 5.2 最高速

```
Veff = vBase × (1 + 0.08 × fSlip + 0.10 × fDrs)
```

- スリップストリームと DRS は足し算で重なる (両方で +18%、619.5 px/秒)
- ピットレーン・自動運転中は `min(Veff, 225)` (game-design.md 8.3 節)
- タイヤの種類・摩耗は最高速に影響しない

### 5.3 加速度の計算

アクセルとブレーキを同時に押した場合は **ブレーキを優先** し、アクセルは 0 として扱う。

```
s = sF (前進中、s ≥ 0)
aEngine  = throttle × accel0 × surfaceAccel × (1 − (s / Veff)²)
aBrake   = brake × brakeDecel × Gbrake
aCoast   = (1 − throttle) × (coastBase + coastDrag × (s / vBase)²)
aScrub   = アンダーステアによる減速 (6.3 節)
aSurface = コース外の追加減速 (7 節)

sF += (aEngine − aBrake − aCoast − aScrub − aSurface) × dt
```

- `(1 − (s/Veff)²)` は速度が上がるほど加速が鈍る形で、空気抵抗も含んでいる。`s > Veff` のとき (スリップストリームが切れた直後など) は負になり、自然に減速する
- ブレーキ・惰性・追加減速で `sF` が 0 をまたいだら 0 で止める (後退には後退の操作でのみ入る)
- `Gbrake` = タイヤのグリップ (10 節) × 路面のブレーキ倍率 (7 節)

### 5.4 後退

- `sF ≤ 6` の状態でブレーキだけを `reverseDelay` (0.3 秒) 押し続けると後退モードに入る
- 後退モードでは、ブレーキ入力で `reverseAccel` で後ろに加速する (最大 `reverseMax`)。アクセル入力は後退を止めるブレーキとして働く (`brakeDecel`)。停止したら前進に戻る
- 後退中の旋回は向きが逆になる (6 節の `sign(sF)`)

### 5.5 目安の数値 (グリップ 1.0)

| 項目 | 値 |
| --- | --- |
| 0 → 500 px/秒 | 2.2 秒 (約 730 px) |
| 最高速 525 → 200 のブレーキ | 約 180 px、0.50 秒 |
| 最高速 525 → 288 のブレーキ | 約 150 px、0.36 秒 |
| 最高速 525 → 375 のブレーキ | 約 100 px、0.23 秒 |
| 最高速でアクセルを離したとき | 約 125 px/秒² で減速 |

ブレーキポイントを 0.1 秒 (最高速で 52 px) 間違えると、ヘアピンではブレーキ距離の約 3 割になる。この感度が「ブレーキ勝負」の面白さの元になる。ブレーキ距離が短すぎると感じたら `brakeDecel` を下げる (500 にすると 525 → 200 が約 205 px)。

## 6. 旋回とグリップ限界

### 6.1 パラメータ

| 名前 | 値 | 意味 |
| --- | --- | --- |
| `latGrip` | 562.5 px/秒² | 横方向に出せる最大の加速度 (グリップ倍率 1.0 のとき) |
| `yawMaxLow` | 3.0 rad/秒 (172°/秒) | 低速での最大旋回速度 |
| `yawRampSpeed` | 50 px/秒 | これより遅いと、旋回速度が速度に比例して小さくなる (止まっていると回れない) |
| `steerDemand` | 1.15 | フルステアで要求する横加速度 = `latGrip × 1.15` (わずかに限界を超える) |
| `scrubRate` | 0.5 | 限界を超えた分の何割を減速にするか |
| `scrubMax` | 150 px/秒² | アンダーステアによる減速の上限 |
| `brakeGripLoss` | 0.25 | フルブレーキ中は横グリップが 25% 減る |

### 6.2 旋回の計算

```
s = |sF|
// フルステアで出せる旋回速度 (速度が上がるほど小さくなる)
yawLimit = min(yawMaxLow × min(1, s / yawRampSpeed), latGrip × steerDemand / s)   // s = 0 のときは 0
yawCmd   = steer × yawLimit × sign(sF)

// 横グリップの限界
aLatMax  = latGrip × G
aReq     = s × |yawCmd|                 // この旋回に必要な横加速度
uReq     = aReq / aLatMax               // グリップ使用率 (1 を超えると限界超え)

yaw = uReq > 1 ? yawCmd / uReq : yawCmd // 限界を超えた分は曲がらない = アンダーステア
θ += yaw × dt
```

`G` (横グリップの倍率) = タイヤ (10 節) × 路面 (7 節) × `(1 − brakeGripLoss × brake)` × DRS が開いていれば 0.9。

考え方:

- 限界内なら入力どおりに曲がる。限界を超えると、そのときの速度で曲がれる最小半径 `R = s² / aLatMax` までしか曲がらず、コーナーのほうが狭ければ外にふくらむ
- `yawLimit` は速度に応じて小さくしてある。そのため **216 px/秒以上では、フルステアの要求は常に `latGrip × 1.15`** になる。キーを押しっぱなしにすると新品タイヤでもわずかに限界を超え (スキール音が鳴り、少し減速する)、当て舵で押したり離したりすると静かに速く曲がれる。アナログスティックなら浅く切るだけで同じことができる。摩耗したタイヤほど超過が大きくなり、アンダーステアが強くなる
- ブレーキを踏みながら曲がると横グリップが減るので、「まっすぐブレーキ → 離して曲がる」ほうが速い

### 6.3 アンダーステアの減速

```
aScrub = uReq > 1 ? min(scrubMax, scrubRate × (aReq − aLatMax)) : 0
```

例: 新品のソフト (G = 1.08) でフルステア → 超過は 646.9 − 607.5 = 39.4 → 約 20 px/秒²。摩耗しきったハード (G = 0.762) なら超過 218 → 109 px/秒²。

### 6.4 横方向の残り速度

接触や壁で生じた横方向の速度 `sR` は、毎フレーム 0 に向かって減らす。

```
sR を 0 に向かって min(|sR|, 750 × 路面のグリップ倍率 × dt) だけ減らす
```

通常の走行では `sR = 0` のまま (向きを変えると、速度の向きも一緒に変わる)。

### 6.5 見た目の滑り角

グリップ限界付近では、車の絵だけを少し内側に向けて「タイヤが滑っている」感じを出す (当たり判定と進行方向は変えない)。

```
描画用の向き = θ + sign(yaw) × clamp((uReq − 0.9) × 25°, 0°, 6°)
```

### 6.6 コーナーの限界速度の目安

`v = √(latGrip × G × R)` (R はレーシングラインの半径、px)

| R (px) | ハード新品 (0.96) | 基準 (1.00) | ソフト新品 (1.08) |
| --- | --- | --- | --- |
| 69 (ヘアピン) | 193 | 197 | 204 |
| 81 (シケイン) | 209 | 214 | 222 |
| 113 | 246 | 252 | 261 |
| 138 | 272 | 278 | 289 |
| 163 | 296 | 302 | 314 |
| 188 | 318 | 325 | 338 |
| 250 | 367 | 375 | 390 |
| 300 | 402 | 411 | 427 |
| 375 | 450 | 459 | 477 |
| 500 | 520 | 530 (全開) | 551 (全開) |

低速側の旋回の限界: 50〜216 px/秒 では `yawMaxLow` の 3.0 rad/秒 で決まり、フルステアでの最小半径は 150 px/秒 で 50 px。

## 7. 路面

車輪 4 点それぞれの路面を調べ、グリップとブレーキは 4 点の平均、追加減速は 4 点の合計 (各 1/4) で決める。片輪だけ芝生に落ちたときに、少しだけ遅くなるようにするため。

| 路面 | グリップ倍率 | ブレーキ倍率 | 加速倍率 `surfaceAccel` | 速度の目安の上限 | 上限を超えているときの追加減速 |
| --- | --- | --- | --- | --- | --- |
| アスファルト (白線を含む) | 1.00 | 1.00 | 1.00 | なし | 0 |
| 縁石 | 0.92 | 0.90 | 1.00 | なし | 0 |
| ピットレーン | 1.00 | 1.00 | 1.00 | なし (速度制限は別) | 0 |
| 芝生 | 0.60 | 0.50 | 0.70 | 225 px/秒 | 437.5 px/秒² |
| 砂利 | 0.45 | 0.40 | 0.50 | 137.5 px/秒 | 687.5 px/秒² |

```
aSurface = Σ(車輪 i) 0.25 × (sF > 上限_i ? 追加減速_i : 0)
surfaceAccel = 4 輪の平均 (加速度にかける)
```

- 4 輪とも芝生のまま 500 px/秒 で突っ込むと、約 0.7 秒・約 250 px で 225 px/秒 まで落ちる。砂利なら約 0.5 秒で 137.5 px/秒 まで落ちる
- 上限以下では追加減速はなく、グリップと加速が落ちるだけ (芝生からは自力でコースに戻れる)
- 壁 (タイヤバリア) は路面ではなく衝突物として扱う (9.2 節)
- 調整: コース外を通ると「得」になる場所 (ショートカット) を見つけたら、その場所を砂利にするか、チェックポイントのゲートで無効にする。数値を強くしすぎると 1 回のミスで勝負が決まってしまうので、芝生の上限は 190〜250 の範囲で調整する

## 8. 限界の演出 (スキール音・タイヤ痕)

| 演出 | 条件 | 強さ |
| --- | --- | --- |
| スキール音 | `uReq ≥ 0.9` かつ速度 ≥ 150 px/秒、アスファルトか縁石の上 | 音量 = `clamp((uReq − 0.9) / 0.3, 0, 1)`。再生速度 = `0.9 + 0.25 × s / vBase` (sound-guide.md の 0.9〜1.15 の範囲)。条件から外れたら 0.15 秒でフェードアウト |
| タイヤ痕 | `uReq ≥ 1.0` かつ速度 ≥ 187.5 px/秒 (アスファルト・縁石) | 後輪 2 点から 2 ドット幅の線を描く |
| タイヤ痕 (ブレーキ) + `tire-lockup` | フルブレーキ (`brake = 1`) を始めてから 0.25 秒間、速度 ≥ 375 px/秒 | 前輪 2 点から線を描く。音は開始時に 1 回だけ鳴らす (物理的なロックはない) |
| スピン中 | スピン中はずっと | スキール音は最大、4 輪からタイヤ痕 |

スキール音は「限界の手前 (0.9)」から鳴り始めることが重要。キーボードでフルステアを保つと 1.15 前後になって鳴り続けるので、プレイヤーは「鳴らないように当て舵する」ことを覚える。

## 9. 接触 (衝撃)

### 9.1 車同士

判定: 当たり判定の長方形 (18 × 38 px、向き付き) 同士を分離軸判定 (SAT) で調べ、めり込み量 `depth` と法線 `n` (A から B へ向かう単位ベクトル) を求める。ゴーストの組み合わせ (game-design.md 7.10 節) は判定しない。

処理:

```
J  = max(0, (vA − vB) · n)          // 接近速度 = 衝撃の強さ (px/秒)
cA = vA · n                          // A が B に向かう速さ
cB = −vB · n                         // B が A に向かう速さ

// 1. 押し戻し
1 人用: A と B をそれぞれ depth / 2 ずつ法線方向に離す
マルチ: 自車だけを depth 分押し戻す (相手の位置は予測値なので動かさない)

// 2. 反発 (質量は全車同じ、反発係数 e = 0.2)
vA −= (1 + e) / 2 × J × n
vB += (1 + e) / 2 × J × n

// 3. 当てた側の判定
cA − cB > 25 なら A が「当てた側」、cB − cA > 25 なら B、差が 25 以内なら両方とも「当てた側」

// 4. 当てた側への追加の減速 (体当たりを損にする)
当てた側の速度ベクトル ×= (1 − min(0.30, J / 1000))

// 5. 当てられた側は押されても速くならない
当てられた側の前方向の速度 sF が接触前より大きくなったら、接触前の値に戻す

// 6. スピン
J ≥ 375 のとき、当てた側はスピン
J ≥ 375 かつ 当てられた側が横から当てられた (|n · 当てられた側の r| > 0.7) なら、当てられた側もスピン
```

- 同じ 2 台の組み合わせでは、最後の衝撃から 0.2 秒以内の衝撃は適用しない (押し戻しだけ行う)。network.md と同じ
- 速度ベクトルを変えたあとは、`sF`・`sR` を新しい速度ベクトルから計算し直す (横方向の成分は 6.4 節で減衰する)
- マルチ: 自車に適用した `J` と `n` を `collision` メッセージで送る。相手がまだ接触を検出していなければ、相手側で同じ計算をして相手の車に適用する。当てた側の判定は両者の速度から同じ式で決まるので、両クライアントで一致する

強さの目安:

| J (px/秒) | 状況の例 | 結果 |
| --- | --- | --- |
| 〜50 | 並走中に軽くこする | 押し戻しのみ。火花なし |
| 50〜187.5 | ブレーキングで軽く追突 | 火花が出て、当てた側が 5〜19% 減速 |
| 187.5〜375 | 大きく追突、横からぶつける | 火花、画面揺れ、当てた側が 19〜30% 減速 |
| 375〜 | ブレーキを忘れて突っ込む | 当てた側がスピン (横から当てたなら両方) |

### 9.2 壁 (タイヤバリア)

```
J = max(0, −v · n)                   // n は壁から車に向かう法線
押し戻し: めり込み分を n 方向へ
法線方向の速度: vN ← −0.2 × vN (はね返り)
接線方向の速度: vT ← vT × (1 − min(0.5, J / 750))
J ≥ 437.5 かつ 壁への進入角が 45° 以上 → スピン
```

演出 (火花・画面揺れ) の条件は車同士と同じ。

### 9.3 スピン

| 項目 | 値 |
| --- | --- |
| 時間 | 1.0 秒 (この間は操作を受け付けない) |
| 回転 | 開始時 8 rad/秒。1.0 秒かけて 0 まで直線的に減らす。回転方向は衝撃の向きから決める (衝撃が車の右側なら反時計回り) |
| 減速 | 625 px/秒² (速度ベクトルの大きさを減らし、向きは変えない = 滑りながら回る) |
| 終了後 | その時点の向き・速度のまま操作が戻る。逆向きなら逆走警告、止まっていればコース復帰が使える |

スピン中は向き θ と進行方向が一致しないので、スピン中だけ速度ベクトルを向きと切り離して扱う。終了時に `sF = v · f`、`sR = v · r` で戻す。

## 10. タイヤ (種類と摩耗)

### 10.1 グリップ

```
タイヤのグリップ = compoundGrip × wearFactor(wear)

compoundGrip: ソフト 1.08、ハード 0.96

wearFactor(w) = 1 − 0.08 × w               (w < 0.7)
              = 0.944 − 0.5 × (w − 0.7)     (w ≥ 0.7、いわゆる「崖」)
w は 1.0 で止める (wearFactor の最小値 0.794)
```

タイヤのグリップは、横グリップ `G` とブレーキ `Gbrake` の両方にかかる。最高速・加速には影響しない。

| 状態 | ソフト | ハード |
| --- | --- | --- |
| 新品 (w = 0) | 1.080 | 0.960 |
| w = 0.35 | 1.050 | 0.933 |
| w = 0.70 (崖の手前) | 1.020 | 0.906 |
| w = 0.85 | 0.939 | 0.834 |
| w = 1.00 | 0.858 | 0.762 |

HUD の摩耗バー (style-guide.md §6) は残り = `1 − w` を表示する。残り 30% (w = 0.7) で赤になり、崖の始まりと一致する。

### 10.2 摩耗

```
L = max(min(uReq, 1.5), 0.8 × brake)                // タイヤへの負荷 (限界超えも数える)
wear += k × (s / vBase) × (0.4 + 0.6 × L) × dt

k: ソフト 0.0155 /秒、ハード 0.0064 /秒
```

- 速度に比例して減るので、止まっていれば減らない (`s / vBase` は比なので、1.25 倍にしても k は変わらない)
- 限界を超えてこする (`uReq > 1`) ほど早く減る。丁寧に走るほど長持ちする
- 目標: 普通に走って 1 周でソフト 0.34 前後、ハード 0.14 前後。実装後にデバッグ表示で 1 周の摩耗を測り、ソフト 0.30〜0.38 / ハード 0.12〜0.16 に入るよう `k` を調整する
- ソフトは 2 周で 0.68 (崖の手前)、3 周目で崖に入る。ハードは 3 周で 0.42 程度
- タイムアタックでは摩耗しない (`wear` を 0 に固定する)。予選・決勝では摩耗する

### 10.3 ラップタイムへの影響 (シミュレーションの目安)

game-design.md 11.2 節のコース案 (1 周 約 17,840 px) を理想走行したときのラップタイム:

| タイヤ | ラップ |
| --- | --- |
| ソフト新品 | 39.6 秒 |
| 基準 (1.0) | 40.2 秒 |
| ハード新品 | 40.5 秒 |
| ソフト w = 1.0 | 41.6 秒 |

ソフトとハードの差は、新品で約 0.9 秒/周。崖に入ったソフトは、新品のハードより約 1 秒遅い。

## 11. スリップストリーム

条件 (前にいる車 L と自車 M について、毎フレーム全車を調べる。決勝のみ):

```
L の後端 = L の位置 − L の f × 19
d = |M の位置 − L の後端|
角度1 = (M の位置 − L の位置) の向き と (−L の f) のなす角
角度2 = M の θ と L の θ の差

有効: d ≤ 150 かつ 角度1 ≤ 20° かつ 角度2 ≤ 30° かつ M の sF ≥ 250 かつ L とゴーストの関係でない
```

- 効き `fSlip`: 有効な間は +2.0 /秒 で上げ (0 → 1 に 0.5 秒)、無効になったら −2.0 /秒 で下げる
- 効果: 最高速 +8% (5.2 節の式)。加速の式が `Veff` を使うので、高速域の加速も良くなる
- 複数の車が条件を満たしても、効果は 1 台分
- HUD にメーターは出さない。風の線のエフェクトと `slipstream-wind-loop` (音量 = `fSlip`) で伝える
- 予選・タイムアタックでは効かない (全車ゴーストで重なって走ることがあり、不自然なため。タイムアタックのゴーストカーからも受けない)

目安: 2,750 px のバックストレートで、スリップストリームだけで約 0.2 秒、DRS だけで約 0.37 秒、両方で約 0.6 秒縮まる (理想走行のシミュレーション)。前車の 0.5 秒後ろにいれば、ストレートの終わりで横に並べる計算。

## 12. DRS

- 使用条件は game-design.md 7.6 節。自車の状態として `drsAvailable` (この周の区間で使える)、`drsOpen` を持つ
- 開く: `drsAvailable` かつ DRS 区間内で `drsPressed`
- 閉じる: ブレーキ入力 (`brake > 0`)、区間の終了ラインの通過、スピン、ピットの自動運転
- 効き `fDrs`: 開くと +5.0 /秒 (0.2 秒で 1)、閉じると −5.0 /秒
- 効果: 最高速 +10% (5.2 節)。開いている間は横グリップ ×0.9 (6.2 節)。開いたままコーナーに入るとふくらむが、ブレーキで自動的に閉じるので、通常は問題にならない

## 13. ピットレーンの自動運転

- ピット入口ラインを越えたら `Controls` を無視し、ピットレーンの経路 (折れ線) を CPU と同じ pure pursuit で追う
- 速度制限は 225 px/秒。入口で 225 を超えていれば `brakeDecel` で自動的に減速する
- ボックス手前で停止位置に合わせて減速し、2.0 秒停止したあと、出口まで 225 px/秒 で走る
- 自動運転中も位置・向き・速度は通常の物理で更新する (ワープしない)。路面判定・壁判定は行わない

## 15. 調整の方針

優先順位 (上ほど先に合わせる):

1. **曲がる感触**: ヘアピン (R 69) と高速コーナー (R 375) を走り、「ブレーキを踏めば曲がれる」「速すぎるとふくらむ」がはっきり分かるか確かめる。分かりにくければ `steerDemand` を上げる (1.2〜1.3)。限界超えが強調される
2. **ブレーキ勝負**: 最高速からヘアピンまでのブレーキ距離 (約 180 px) が短すぎたり長すぎたりしないか。`brakeDecel` で調整する
3. **ラップタイム**: 43〜48 秒に入るか。外れたらコースの直線の長さで調整する (車の性能は 1・2 で決めたものを動かさない)
4. **コース外**: 芝生に落ちたときの損失が、ミス 1 回につき 0.5〜1.5 秒程度か
5. **追い抜き**: CPU 相手に、DRS 区間で 0.5 秒差から横に並べるか。並べなければ `slipBonus` / `drsBonus` を上げる
6. **タイヤ**: game-design.md 8.1 節の 4 つの戦略の差が 1 秒以内に収まるか
7. **キーボードとゲームパッドの差**: 同じ人が両方で走ってタイム差が 0.5 秒/周 を超えるなら、キーボードの `steerRise` を上げるか `steerDemand` を下げる

実装時は、F3 のデバッグ表示で `s`、`uReq`、`G`、路面、`fSlip`、`fDrs`、`wear` を常に見られるようにする。
