## 2. コンセプトと面白さの柱

**「ブレーキを遅らせ、ラインを削り、0.1 秒を詰める」見下ろし型 F1。**
3 分で終わる短いレースの中に、スタートの反応、ブレーキ勝負、スリップストリームと DRS からの追い抜き、タイヤ戦略を詰め込む。

面白さの柱 (仕様判断に迷ったらここに戻る):

1. **速さは技術で決まる**: ドリフトではなく、ブレーキポイントとライン取りで差がつく。速すぎれば外にふくらむ (アンダーステア)。限界はスキール音とタイヤ痕で耳と目に伝える
2. **抜く・抜かれるの駆け引き**: スリップストリーム、DRS、ブレーキング勝負で追い抜きが起きる。体当たりは得にならない (当てた側も損をする)
3. **短い時間に戦略がある**: 3 周でも「ソフト/ハードをどの順でいつ履くか」でレース展開が変わる (義務ピット)
4. **中継の気分**: 順位表のタイム差、区間タイムの紫/緑、ファステストラップ通知など、F1 中継風の情報で「いま何が起きているか」が分かる
5. **1 周がすぐやり直せる**: タイムアタックはリトライが速く、自己ベストのゴーストと競える

## 3. コアループ

```
[走る] コーナーごとにブレーキ・ライン・アクセルの判断
   ↓ 結果がすぐ返る (区間タイムの色、前車との差、ゴースト差)
[比べる] 自己ベスト/ライバルとの差を知る
   ↓
[改善する] 次の周・次のレースでブレーキを遅らせる、ラインを変える、戦略を変える
   ↓
[記録・順位が上がる] 自己ベスト更新、ゴースト更新、表彰台
```

- 短いループ (数秒): 1 コーナーごとの成否 (スキール音、ふくらみ、立ち上がり速度)
- 中くらいのループ (約 40 秒): 1 周ごとの区間タイム・ラップタイム・順位変動
- 長いループ (約 3 分): レース結果、戦略の成否、自己ベスト更新

## 5. 操作

### 5.1 キーボード (基本)

| 操作 | キー (`KeyboardEvent.code`) | 取得方法 |
| --- | --- | --- |
| アクセル | `ArrowUp` / `KeyW` | `isDown` |
| ブレーキ / 後退 | `ArrowDown` / `KeyS` | `isDown` (停止中に 0.3 秒押し続けると後退) |
| 左に曲がる | `ArrowLeft` / `KeyA` | `isDown` |
| 右に曲がる | `ArrowRight` / `KeyD` | `isDown` |
| DRS | `Space` | `wasPressed` (開くだけ。閉じるのはブレーキ/区間終了) |
| コース復帰 | `KeyR` | `wasPressed` (条件を満たすときのみ有効、9.9 節) |
| ポーズ | `Escape` | `wasPressed` (マルチでは一時停止せずメニューを重ねて表示) |
| ピットでのタイヤ選択 | `ArrowLeft`/`ArrowRight` (`KeyA`/`KeyD`) | `wasPressed` (ピット停止中のみ) |
| デバッグ表示 (開発用) | `F3` | `wasPressed` |

- メニュー: 上下で選択、`Enter` / `Space` で決定、`Escape` で戻る
- ステアリングは **車基準** (左キー = 車から見て左へ曲がる)。カメラは北が上で固定なので、南向きに走っているときは画面上の左右と逆になる。これはトップダウンのレースゲームで一般的な操作で、採用する
- キーボードの左右は 0/1 の入力だが、車側で滑らかに立ち上げる (car-physics.md 3 節)
- キー割り当ての変更機能は作らない (未決定事項に記載)

### 5.2 ゲームパッド (提案: M3 で対応)

推奨: **M3 で対応する**。Gamepad API で標準マッピングを読むだけなので実装コストが小さく、アナログのアクセル・ステアは「限界の手前で曲がる」遊びと相性が良い (キーボードより滑らかに走れる)。

| 操作 | ボタン (標準マッピング) |
| --- | --- |
| アクセル | RT (buttons[7]、アナログ 0〜1) |
| ブレーキ / 後退 | LT (buttons[6]、アナログ 0〜1) |
| ステア | 左スティック X (axes[0])。デッドゾーン 0.15 |
| DRS | A (buttons[0]) |
| コース復帰 | Y (buttons[3]) |
| ポーズ | Start (buttons[9]) |

キーボードとゲームパッドは同時に使える (大きい方の値を採用)。`src/core/Input` の拡張が必要なので game-engineer の担当。

### 5.3 入力の抽象化 (実装上の要件)

車は `Controls` (throttle 0〜1, brake 0〜1, steer -1〜1, drsPressed, resetPressed) だけを見て動く。キーボード・ゲームパッド・CPU の AI・ゴーストの再生・ネットワークはすべて `Controls` または車の状態を作る側として実装する。M4 のマルチで同じ物理計算をサーバーと共有するための前提。

## 7. レースのルール

### 7.1 セッションの種類

| セッション | 目的 | 周回 | 他車との接触 | タイヤ摩耗 | DRS | ピット |
| --- | --- | --- | --- | --- | --- | --- |
| タイムアタック | 自己ベスト更新 | 無制限 | なし (ゴーストのみ) | なし (ソフト固定) | 区間内で自由に使用可 | 入れない (入ると周回無効) |
| 予選 | グリッド決定 | 計測 2 周 | なし (全車ゴースト) | あり (ソフト新品で開始) | 区間内で自由に使用可 | 入れない (入ると周回無効) |
| 決勝 | 順位を競う | 3 周 (標準) / 5 周 | あり | あり | 条件付き (7.6 節) | あり、義務 1 回 (8 章) |

### 7.2 スタート (決勝)

1. 全車がグリッドに並ぶ (7.3 節)。操作は受け付けるが、この時点で動くとフライング
2. 1.0 秒後から、赤ランプが 1.0 秒間隔で 1 灯ずつ点灯 (計 5 灯)。点灯ごとにビープ音
3. 5 灯点灯後、**0.5〜2.5 秒のランダム時間** (一様分布) 待って全消灯 = スタート
4. 消灯の瞬間からレース時間の計測を開始。HUD に反応時間 (消灯からアクセルを踏むまで、例「反応 0.231 秒」) を 2 秒表示

フライング:

- 判定: 消灯前に車がグリッド位置から **4 px 以上** 動いたら成立 (1 回のみ判定)
- 罰則: **ゴールタイムに +3 秒**。成立した瞬間にブザー音と「フライング +3 秒」を 3 秒表示。順位表の名前の横にペナルティ表示
- 車はそのまま走れる (止めない)。CPU は消灯後 0.15〜0.40 秒 (難易度で変化) で発進するのでフライングしない
- マルチではホストが消灯時刻を決め、各クライアントの位置報告から判定する

### 7.3 グリッド

- コントロールライン (スタート/フィニッシュライン) の手前に 2 列の千鳥配置
- k 番手 (k = 0〜7) の位置: コントロールラインから中心線沿いに **20 + 40k px** 後方、横方向は中心線から **k が偶数なら -12 px、奇数なら +12 px** (ポールは次の 1 コーナーのイン側に置く。コースデータで左右を指定)
- 車の向きはコースの進行方向
- グリッド順: 予選順位。予選スキップ時はプレイヤーが最後尾、CPU はランダム (理由: 予選を走る動機を残す。12 章で再確認)

### 7.4 周回とチェックポイント

- コースには進行順に並んだ **チェックポイント** (約 600 px ごと、1 周 20〜26 個) があり、各車は「次に通るべきチェックポイント番号」を持つ
- 次のチェックポイントを通過したときだけ番号が進む。コントロールラインは番号 0 のチェックポイントで、全チェックポイントを通過した状態で通ったときだけ周回数 +1
- チェックポイントは線分 (ゲート) で、幅はコース + 外側のランオフ全体 (コースアウトしただけでは無効にならない)。シケインのショートカット側 (イン側) だけはゲートの外にする
- 次のチェックポイントを飛ばして先のゲートを通った場合は「チェックポイント未通過」状態になり、HUD に「コースに戻ってください」と矢印 (未通過ゲートの方向) を表示。この状態ではコース復帰 (9.9 節) がいつでも使える
- グリッドはコントロールラインの手前なので、スタート直後の最初の通過は周回に数えない (1 周目の開始)。1 周目のラップタイムは消灯から計測

### 7.5 順位とタイム差

- 進行距離 `P = 周回数 × 1 周の長さ + 中心線上の位置` で順位を決める。中心線上の位置は「直前に通過したチェックポイント」と「次のチェックポイント」の間に制限する (ショートカットで順位が上がって見えないように)
- ゴールした車はゴール順が優先
- **タイミングライン**: 中心線沿いに 200 px ごと (1 周 約 70 本) に置き、各車の通過時刻を記録する
- 前車とのタイム差 = 自分が最後に通過したタイミングラインの時刻 − 前車が同じ周・同じラインを通過した時刻。ライン通過ごとに更新
- 表示: 1 分未満は「+1.234」、1 分以上は「+1:02.345」、周回遅れは「+1 LAP」
- 区間 (セクター): 1 周を 3 区間に分ける。境界はコースデータで指定し、所要時間が概ね均等になる位置にする

### 7.6 スリップストリームと DRS (ルール面)

数値と判定の詳細は car-physics.md。

- スリップストリーム: 決勝のみ有効 (予選・タイムアタックは全車ゴーストのため効かない)
- DRS 区間: コースに 1 か所 (バックストレート)。区間の手前に **検知ライン** を置く
- 決勝では、**2 周目以降**、検知ラインで前車とのタイム差が **1.000 秒以内** ならその周の DRS 区間で使用可能
- 予選・タイムアタックでは、DRS 区間内なら条件なしで使用可能
- 使用可能な状態で区間内に入ったら `Space` で開く。ブレーキを踏む、または区間の終わりで自動的に閉じる。一度閉じたらその区間では再度開けない

### 7.7 レースの終了と順位確定

- 先頭車が規定周回を終えた時点でチェッカーフラッグ。以降、各車は次にコントロールラインを通過した時点でゴール
- 先頭車のゴールから **30 秒** 経ってもゴールしていない車は、その時点の順位で「未完走 (+n LAP)」
- 1 人用: プレイヤーがゴールした時点で、残りの CPU は「残り距離 ÷ その CPU の直近 1 周の平均速度」でゴールタイムを推定して即座に確定し、リザルトへ (待たせない)
- 最終順位 = ゴールタイム + ペナルティ (フライング +3 秒、義務ピット未消化 +30 秒) の小さい順。ゴールした車 → 未完走の車 (進行距離順) → リタイアの順
- 1 人用ではポーズメニューから「リタイア」できる (結果は DNF)
- マルチではホストが最終順位を確定して `result` で送る

### 7.8 予選

- 開始位置: コントロールラインの **700 px 手前** (最終コーナーの立ち上がり付近) に停止した状態。カウント 3-2-1 のあと発進 (スタートランプは使わない)
- 計測 2 周。2 周のうち有効な周のベストがその車の予選タイム。2 周目の終了でセッション終了
- 周回が無効になる条件: チェックポイント未通過、コース復帰の使用、ピットレーンへの進入。無効な周は HUD に「INVALID」を表示し、タイムを灰色にする
- 全車ゴースト (接触なし)。マルチでは全員同時に同じ位置から出るが、重なっていても問題ない
- 1 人用の CPU は実際には走らせず、タイムを計算で出す: `CPU 予選タイム = コースの基準タイム × (1 + (1 − 腕前) × 1.2) + 乱数(−0.2〜+0.4 秒)`。基準タイムは腕前 1.0 の CPU の実測ラップ (コースデータに記録)
- 有効なタイムがない車はグリッド後方 (その中ではランダム)

### 7.9 接触

- 車同士は当たり判定あり (決勝のみ)。当てた側 (接近速度が大きい側) の方が大きく減速し、強く当てると当てた側がスピンする。当てられた側が押されて速くなることはない。数値は car-physics.md 9 節
- 壁 (ランオフの外側のタイヤバリア) にも当たり判定がある
- 車のダメージ (壊れる・遅くなる) はない

### 7.10 ゴースト (すり抜け) になる条件

| 条件 | 対象 | 期間 |
| --- | --- | --- |
| 周回遅れの関係 | 2 台の進行距離の差が 1 周の長さの半分以上ある組み合わせ | 条件を満たす間ずっと (その 2 台の間だけ) |
| コース復帰直後 | 復帰した車 ↔ 全車 | 操作再開から 3.0 秒 |
| ピットレーン走行中 | ピットレーン内の車 ↔ 全車 | ピット入口ラインからピット出口ラインまで + 出口後 1.0 秒 |
| 予選・タイムアタック | 全車 | 常時 |

- 期間の終わりに他車と重なっている場合は、重ならなくなるまでゴーストを延長する
- ゴースト中の車は半透明 (不透明度 50%) で描く。コース復帰直後とピット出口後は 4 回/秒で点滅 (50% ↔ 80%)
- 周回遅れの関係は常に解除されうる (例: 抜いた後に離れれば条件が外れる) が、半分周以上の差があるので実際に近づくのは追い抜きの瞬間だけ。合意済みの「周回遅れの車は数秒ゴースト」を、判定が単純で全クライアントで一致しやすい「周回遅れの組み合わせは接触しない」で実現する

### 7.11 コース復帰 (リセット)

使える条件 (決勝・予選・タイムアタック共通、スタート前・ピットレーン内・スピン中は不可):

- 速度 50 px/秒 未満が 1.0 秒以上続いている、または
- 4 輪すべてがコース外 (芝生・砂利) の状態が 1.5 秒以上続いている、または
- 逆走警告 (10.3 節) が出ている、または
- チェックポイント未通過状態

条件を満たすと HUD に「R: コース復帰」を表示。満たさないときに押すと「今は復帰できません」を 1 秒表示。

手順:

1. 0.3 秒で画面を暗転 (自車だけ。マルチでは他の人の画面には影響しない)
2. 「最後に正常に走っていた地点」(コース上かつチェックポイント順が正しかった最後の位置) から中心線沿いに **120 px 手前** に、中心線上・進行方向向き・速度 0 で置き直す
3. 0.3 秒で明転し、**1.5 秒** 操作不能 (「復帰中」とカウント表示)
4. 操作再開と同時に 3.0 秒のゴースト (7.10 節)

時間の損失は置き直し分と停止からの加速を含めて約 4 秒 (ペナルティとして十分で、ショートカットの得にならない)。予選・タイムアタックでは、その周は無効。

## 8. ピットとタイヤ

### 8.1 3 周レースで意味を持たせる方法 (決定)

検討した選択肢:

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A. 摩耗だけ | ソフトは速いが 3 周目に崖 | ピットの損失 (約 6.5 秒) を取り返せないため誰もピットに入らない。ピットの意味が薄い |
| B. 義務ピット 1 回 | 1 回タイヤ交換必須 | 同じタイヤを 2 回履けば最速になり、選択の幅が狭い |
| **C. 義務ピット 1 回 + 2 種類使用義務** | ソフトとハードを両方使う | **採用**。「どちらを先に履くか」「何周目に入るか」の 2 軸で展開が分かれる |
| D. 周回数を長くする | 8 周以上 | 合意済みの「標準 3 周・約 3 分」と合わない。5 周の選択肢だけ追加する |

決定:

- 決勝では **ソフトとハードの両方を使う義務** がある。スタート時のタイヤ + ピットで履いたタイヤで判定するので、実質 **1 回以上のピットイン** が必要
- 義務を果たさずにゴールした場合 **+30 秒** (ピットの損失約 6.5 秒より十分大きく、義務を無視する得がない)
- HUD の自分の欄に義務の状態を表示 (未消化: 「PIT 未」、消化済み: チェックマーク)
- 周回数は 3 周 (標準) / 5 周 を選べる

想定されるレース展開 (シミュレーションによる目安、ラップ約 40 秒のコース):

| 戦略 (3 周) | 1 周目 | 2 周目 | 3 周目 | 合計の差 (ピット損失を除く) |
| --- | --- | --- | --- | --- |
| ソフト 2 周 → ハード 1 周 | 速い | やや速い | 遅い | 基準 |
| ハード 1 周 → ソフト 2 周 | 遅い | 速い | やや速い | 基準と同じ |
| ソフト 1 周 → ハード 2 周 | 速い | 遅い | 遅い | +0.7 秒 |
| ハード 2 周 → ソフト 1 周 | 遅い | 遅い | 速い | +0.7 秒 |

- ソフト 2 周が最もバランスが良いが、滑らせる走りをするとソフトが 2 周目で崖に入る (car-physics.md 10 節)。「ソフトで前に出て守る」か「ハードで耐えて最後に新品ソフトで追う」かの選択になる
- 前の車より先にピットに入って新品タイヤで差を詰める (アンダーカット) も成立する
- スタートタイヤはレース設定で選ぶ (マルチはロビーで各自選ぶ)

### 8.2 タイヤの種類

| 種類 | 表示色 | グリップ | 摩耗の速さ (1 周の目安) |
| --- | --- | --- | --- |
| ソフト (S) | 赤 | ×1.08 | 約 34% |
| ハード (H) | 白 | ×0.96 | 約 14% |

- 摩耗が 70% を超えると急にグリップが落ちる (崖)。100% で止まり、それ以上は悪化しない (パンクなし)
- 摩耗で変わるのはグリップ (旋回の限界とブレーキ) のみ。最高速・加速は変わらない
- 詳細な式は car-physics.md 10 節
- 中間のミディアムは作らない (3 周では違いが出にくく、選択が複雑になるだけ。5 周以上を増やす場合に再検討)

### 8.3 ピットレーン

コース上の配置: ピット入口は最終コーナー手前のイン側で分岐、ピットレーンはメインストレートと平行、出口は 1 コーナーの先で合流 (長さ約 1,300 px)。ピットレーン内でもコントロールラインの通過は有効 (周回が数えられる)。

状態遷移 (ピット入口ラインを越えた時点から自動運転):

```
RACING ──(ピット入口ラインを通過)──→ PIT_IN
PIT_IN   : 自動運転。速度制限 180 px/秒 まで自動でブレーキ (減速度 450 px/秒²)。操作無効
  ↓ ピットレーン本線に到達
PIT_LANE : 自動運転で 180 px/秒 を維持してピットボックスへ
  ↓ ボックス到着 (停止)
PIT_STOP : 2.0 秒 停止してタイヤ交換。左右キーでタイヤを選ぶ (停止から 1.5 秒まで変更可)
  ↓ 交換完了 (摩耗 0% の新品になる)
PIT_OUT  : 自動運転で 180 px/秒、ピット出口ラインまで
  ↓ ピット出口ラインを通過
RACING   : 操作が戻る。速度制限解除。ゴースト 1.0 秒 (7.10 節)
```

- ピットレーン内は全車ゴースト (接触なし)。自動運転なので渋滞・衝突の処理は不要。ボックスは 8 台分あり、各車に 1 つ割り当てる (グリッド順)
- タイヤ選択の既定値: 2 種類使用義務が未消化なら「今と違う種類」、消化済みなら「ソフト」
- ピットインによる損失は約 6.5 秒 (レーン走行 7.2 秒 + 停止 2.0 秒 − 同区間をコースで走る約 3.3 秒 + 減速・加速分)
- 最終周にピットレーンに入った場合はドライブスルー (停止・交換なし) で通過する
- 予選・タイムアタックでピットレーンに入った場合も同じ自動運転で通過し、その周は無効
- ピットに入る意思表示のボタンは作らない (入口に向かって走れば入る)。ただし入口ラインの手前 300 px に路面の矢印と「PIT」看板を置いて誤進入を減らす

## 9. CPU 車

### 9.1 走り方

- コースデータの **レーシングライン** (中心線とは別の折れ線、各点に目標速度) に沿って走る。目標速度は曲率半径 R から `√(450 × タイヤのグリップ × R) × 腕前` で事前計算
- ステア: レーシングライン上の先読み点 (距離 40 px + 速度 × 0.25 秒) に向けて曲がる (pure pursuit)
- アクセル・ブレーキ: 先の目標速度に間に合うブレーキ開始点を、減速度 450 × グリップ × 0.95 で計算して判断する
- プレイヤーと同じ物理 (`Controls` を出力する) で走る。ズルはしない

### 9.2 難易度

| 難易度 | 腕前 (目標速度とブレーキの倍率) | コーナーでのミス率 | スタート反応 |
| --- | --- | --- | --- |
| Easy | 0.88 | 8% (ブレーキ開始が 30 px 遅れてふくらむ) | 0.30〜0.40 秒 |
| Normal | 0.94 | 4% | 0.20〜0.32 秒 |
| Hard | 0.98 | 1.5% | 0.15〜0.25 秒 |

- 各 CPU の腕前に ±0.01 の個体差を付ける (同じ難易度でも速い車と遅い車ができる)
- ラバーバンド (遅れた車を速くする補正) は **入れない**。実力差は難易度選択で調整する

### 9.3 レース中の判断

- 追い抜き: 前車が 80 px 以内で自分より遅いとき、空いている側へ最大 20 px ラインをずらす (最大 3 秒)
- 追突回避: 前車が 40 px 以内で接近しているときはブレーキ
- DRS: 使用可能なら区間に入ってすぐ開く
- タイヤ戦略: 規則を満たす戦略 (8.1 節の 4 通り) からランダムに選ぶ。Hard の CPU はソフト 2 周系を選ぶ確率を高く (60%) する
- スタックしたら (速度 50 px/秒 未満が 2 秒) コース復帰を使う

### 10.5 カメラ

- 北が常に上 (回転しない)。倍率は 1.0 固定 (ワールドの 1 px = 画面の 1 px)
- 追従先 = 自車の位置 + 速度ベクトル × 0.4 秒 (長さは最大 150 px) → 進行方向の先が多く見える
- カメラは追従先へ指数的に近づける: `camera += (target − camera) × (1 − e^(−4 × dt))`
- ただし自車が画面中央から横 ±250 px、縦 ±170 px の外に出ないよう制限する
- 画面揺れはカメラ位置に加算する
- スタート前はグリッドの自車を中心に置く

## 12. 開発段階ごとの範囲

**1 人用を先に作り、マルチは最後。** 各段階の終わりに「遊べる状態」になるように区切る。

### M1: 走る楽しさ (タイムアタック)

最初にタイムアタックを作る理由: 車の挙動とコースの調整がゲームの面白さの大半を決め、AI なしで検証できる。ゴーストは位置を記録・再生するだけで安く作れる。

- タイトル → メニュー → タイムアタック → ポーズ
- 車の物理 (スリップストリーム・接触・タイヤ摩耗を除く)、路面、壁、DRS (区間内で自由に使用)
- コース 1、カメラ追従、チェックポイント・周回・区間タイム・色分け
- コース復帰、逆走警告
- ゴースト: 自己ベスト周の位置と向きを 30 回/秒 記録し、`localStorage` に保存 (1 周 約 18 KB)。物理のバージョン番号も保存し、違う場合は破棄
- HUD ②③ (タイヤ表示なし) と ⑤、ゴースト差表示
- タイヤ痕、スキール音、エンジン音、コース外の音、メニュー音
- デバッグ表示 (F3): 速度、グリップ使用率、グリップ倍率、路面、スリップ/DRS の効き、摩耗
- 絵は仮 (図形) でもよい。M1 の終わりに正式な車とコースのタイルを入れる

### M2: CPU とのレース

- レース設定画面、CPU 車 (AI、難易度)、グリッド、スタートランプ、フライング
- 順位・タイム差・順位表 (①)、ミニマップ (④)、順位変動表示
- 車同士の接触、火花、画面揺れ、ゴースト規則 (周回遅れ・復帰直後)
- スリップストリーム、決勝の DRS 条件
- チェッカー、リザルト画面、リタイア
- この段階の決勝は予選なし (レース設定のグリッド順: プレイヤー最後尾、CPU ランダム)、ピットなし、タイヤはソフト固定・摩耗なし

### M3: 戦略・予選・仕上げ

- タイヤの種類と摩耗、ピットレーン、義務ピット、スタートタイヤの選択、周回数 5 の選択肢
- 予選と予選結果画面
- ファステストラップ通知、ペナルティ表示、HUD の仕上げ
- ゲームパッド対応 (推奨)
- 設定画面の全項目、BGM、全 SE、背景の装飾・タイトルロゴ

### M4: マルチプレイ

- network.md の実装ステップ 1〜6 (Transport、ホストサーバー、ロビー、状態の送受信、ホストによるレース進行、接触、切断処理)
- ホストが判定するもの: スタート時刻、フライング、周回・チェックポイント、順位、ゴール、ペナルティ、義務ピット、ゴースト状態 (周回遅れの関係)
- 各クライアントが計算するもの: 自車の物理、ピットの自動運転、コース復帰 (ホストに通知)
- 予選 → 決勝 → リザルト → ロビー

**M1 から守る実装上の前提** (M4 で作り直さないため): 車の物理とコース判定は DOM に依存しない純粋な計算として共通化できる場所 (network.md の案では `src/shared/`) に置く / 車は `Controls` で動かす / パラメータは 1 か所の設定オブジェクトにまとめる / 固定タイムステップ 1/60 秒で計算する。
