## 1. 全体の方針

| 項目 | 方針 |
| --- | --- |
| コンセプト | 「90 年代のアーケード / 16 ビット機のレースゲーム」。ピクセルアートの見た目に合わせ、BGM はレトロな電子音、SE は実車らしさを残しつつ短く・乾いた音にする |
| BGM のジャンル | チップチューン + シンセウェーブ (FM シンセ風のベース、アルペジオ、打ち込みドラム)。歌なし |
| SE の質感 | 走行系 (エンジン・タイヤ・接触・コース外) は実車寄りのリアルな音。UI・スタートシグナル・ラップ通知などの「中継・画面」系はチップチューン寄りの電子音 |
| 残響 | 全体に残響 (リバーブ) なしの乾いた音で作る。距離感はゲーム側の音量・こもり (ローパス) で出す |
| チャンネル | BGM はステレオ、SE はすべてモノラル (左右の定位はゲーム側で付ける) |
| 形式 | OGG Vorbis、44.1 kHz。配置は `public/assets/sounds/bgm/`・`public/assets/sounds/se/` |

### ピクセルアートとの統一感

- 「見た目はレトロ、音もレトロ」を BGM と UI 系の SE で担う。走行系の SE まで 8 ビット音にすると、グリップ限界のスキール音やスリップストリームなど**遊びの情報を伝える音が聞き分けにくくなる**ため、走行系は実車寄りにする
- 走行系 SE は「高音質な実録音」ではなく「アーケード筐体から鳴る音」を目指す: 短く、アタックがはっきりし、低音を盛りすぎない
- 実車寄りの SE が浮いて聞こえる場合は、変換時に軽いビット落とし・高域カットを入れる処理の追加を検討する (現状の変換スクリプトには無い。必要になったら提案する)

## 2. BGM

| 曲 | 画面 | テンポ | 雰囲気 | 長さ・ループ |
| --- | --- | --- | --- | --- |
| menu-theme | メニュー | 115〜125 bpm | 落ち着いたシンセウェーブ。夜の高速道路、期待感 | 60〜90 秒ループ |
| qualifying-theme | 予選 | 130 bpm 前後 | 抑えた緊張感。ドラムとベース中心、メロディは控えめ | 60〜90 秒ループ |
| race-theme | レース | 150 bpm (テスト生成で試聴 OK) | 疾走感。ドライビングベース + アルペジオ | 60〜90 秒ループ |
| result-theme | リザルト | 100〜110 bpm | 達成感、ゆったり | 30〜60 秒ループ |
| ジングル類 | ゴール・優勝など | 曲に合わせる | 短いファンファーレ | 2〜6 秒、ループなし |

- **メニューとレースで雰囲気を分ける**: メニューは中速・余裕のある音、レースは速く前のめり
- **レース中の BGM はエンジン音・スキール音の邪魔をしない**: 中低域 (ベース・キック以外の 200〜800 Hz 付近) を詰め込まない。プロンプトに「clean mix, light」を入れ、厚いパッドや歪んだギターは避ける
- ピット・スタートシグナルには専用 BGM を作らない。スタートシグナル中は BGM を止めるか大きく下げ (ダッキング)、消灯と同時にレース BGM を始める (実況中継の「静寂 → 爆発」の演出)
- ACE-Step の出力は曲頭にイントロ、末尾にフェードが入りやすい。変換時に `--start` / `--end` で切り落としてからループ化する

## 3. SE の考え方

### エンジン音

- **1 本のループ (一定回転数) を再生速度 (ピッチ) で変化させる**。回転数ごとに別の音は作らない
- ループ素材は「中くらいの回転数」で録った音にし、再生速度 1.0 がレンジの中央付近になるようにする (上げ下げどちらにも余裕を持たせる)
- 生成時は 4〜6 秒生成し、回転が一定な中央部分を切り出してループ化する (後述の「変換時の注意」)
- アクセル ON 用 (`engine-player-loop`) と OFF 用 (`engine-player-decel-loop`、減速時のこもった音) を用意し、アクセル量でクロスフェードする (OFF 用は優先度中。無い間は ON 用の音量とピッチだけで表現する)

| 項目 | 推奨値 |
| --- | --- |
| 再生速度の範囲 | 0.55 (アイドリング) 〜 1.9 (レッドゾーン)。約 -10 〜 +11 半音 |
| 超えないこと | 0.5 未満 / 2.0 超は音質の劣化 (こもり・ザラつき) が目立つため使わない |
| ギアの表現 | 各ギア内で回転数が上がり、シフトアップで下がるノコギリ状のカーブにする (速度に比例させるだけだと単調になる)。ギア数は 6〜8 段程度 |
| 変化のなめらかさ | 再生速度・音量はフレームごとに直接代入せず、`setTargetAtTime` などで 30〜50 ms かけて追従させる (ジッパーノイズ防止) |
| アクセル量と音量 | アクセル OFF 時は ON 時の 0.6 倍程度に下げる |

### 8 台同時再生 (他車のエンジン音)

- 他車は別素材 `engine-cpu-loop` (自車より細く軽い音) を使い、**自車の音と聞き分けられる**ようにする。初版は自車ループを流用し、ローパスで少しこもらせてもよい
- 同じ素材を複数台で鳴らすと位相が揃って「ワンワン」とうなる (コムフィルター)。車ごとに次をずらす:
  - 再生開始位置をランダムにする (`start(0, random * duration)`)
  - 再生速度に ±3% の個体差 (固定値) を掛ける
- **同時に鳴らす他車エンジンは近い順に最大 4 台**。それ以外は音量 0 で停止しておく (8 人対戦でも自車 + 4 台 = 最大 5 本)
- 全体の音割れ防止に、マスターの手前にコンプレッサー (`DynamicsCompressorNode`) を 1 つ入れる

### 距離による減衰・左右の定位

聞き手 (リスナー) は**自車**とする (カメラが自車を追う前提。カメラ中心が自車から大きくずれる演出を入れる場合はカメラ中心にする)。

| 項目 | 推奨 |
| --- | --- |
| 減衰 | 距離 d (px) に対し、`d ≤ 80` で 1.0、`d ≥ 700` で 0、その間は `(1 - t)²` (t は 0〜1 に正規化した距離) で下げる。画面 (800×600) の外に出た車はほぼ聞こえない程度 |
| こもり | 距離に応じてローパスの周波数を 8 kHz (近い) → 1.5 kHz (遠い) に下げる。遠くの車が「遠く」聞こえ、近くの車との区別がつく |
| 左右の定位 | `StereoPannerNode` で `pan = clamp(dx / 400, -1, 1) × 0.7`。dx は画面上の横方向の差。完全に左右へ振り切らない (0.7 まで) |
| カメラの回転 | カメラが車の向きに合わせて回転する場合は、画面上の座標 (回転後) で dx を求める |
| 対象 | 他車のエンジン・スキール・接触音。自車の音と UI・BGM には減衰も定位も掛けない (自車は中央) |
| ドップラー効果 | 初版では入れない。入れる場合は相対速度に応じて再生速度を ±5% 以内で変える |
| スリップストリーム | 前車の真後ろにいるとき、前車のエンジン音を少し上げ (+20% 程度) 風切り音 `slipstream-wind-loop` を重ねると「吸い込まれる」感覚が出る |

### タイヤのスキール (グリップ限界の通知)

- 面白さの軸なので、**ワンショットではなくループ**にして、横滑りの量 (スリップ率) に応じて音量と再生速度を連続的に変える
  - 限界手前 (スリップ率がしきい値の 80% 付近) から小さく鳴り始め、限界を超えると大きくなる。「鳴り始め = 限界が近い」合図になる
  - 音量 0 〜 1.0、再生速度 0.9 〜 1.15 程度
- ループは 2 種類作り、車ごとに割り当てて単調さを避ける
- 急ブレーキのロック音 (`tire-lockup`) はワンショットで別に用意する

### 接触 (火花)

- ワンショット、**3 種類のバリエーションをランダムに選ぶ**。再生速度にも ±8% のランダムを掛ける
- 衝突の強さ (相対速度) で音量を変える。弱い接触は 0.3、強い衝突は 1.0
- 同じ車の組み合わせで 0.15 秒以内に再発生した場合は鳴らさない (押し付け合いで連打になるのを防ぐ)。壁に擦り続ける間は `scrape-loop` を鳴らす
- 衝突音は瞬間的な音のため、ピーク -1 dBFS の制限で平均ラウドネスが -26 LUFS 程度と低く測定されるが、体感の音量は十分なことが多い。ゲーム側の音量は測定値ではなく試聴で決める

### コース外

- 芝生・砂利は路面にいる間だけ鳴るループ。速度に応じて音量 (0.2〜1.0) と再生速度 (0.8〜1.2) を変える
- 縁石 (ランブル) も同じ扱いのループ

## 4. 音量バランス

### ファイル側の基準 (変換スクリプトの既定値)

| 種類 | ラウドネス | ピーク |
| --- | --- | --- |
| BGM | -18 LUFS | -1 dBFS 以下 |
| SE | -16 LUFS | -1 dBFS 以下 (短い音は頭打ちで -16 LUFS に届かないことがある) |

ファイル側はこの基準に揃え、ゲーム内のバランスは再生側の音量 (ゲイン) で決める。

### ゲーム側のグループと推奨音量 (初期値。試聴で調整する)

音量はグループ (バス) 単位でまとめ、オプション画面で「BGM」「効果音」の 2 つを調整できるようにする。

| グループ | 対象 | 推奨ゲイン |
| --- | --- | --- |
| BGM (メニュー・リザルト) | menu-theme, result-theme | 0.7 |
| BGM (予選・レース) | qualifying-theme, race-theme | 0.4 (エンジン音を主役にする) |
| 自車エンジン | engine-player-* | 0.4 |
| 他車エンジン | engine-cpu-loop | 0.3 × 距離減衰 |
| タイヤ・コース外 | tire-*, offtrack-*, kerb-* | 0.45 |
| 接触 | crash-*, scrape-loop | 0.6 |
| 中継・通知 | start-light-*, lap-*, sector-*, drs-* | 0.8 |
| UI 操作音 | ui-* | 0.6 |

- スタートシグナル中は BGM を 0 (または 0.1) に下げる。ゴール時のジングル中はレース BGM を止める

### 走行系の抑え方 (ユーザー指示: 大きく耳障りにしない)

走行系 (エンジン・タイヤ・コース外・接触) は、ずっと鳴り続けるため疲れやすい。次の 4 点で控えめにする。

1. **音量**: 上の表のとおり、当初案 (エンジン 0.6 / タイヤ 0.7 / 接触 0.9) から約 3 分の 2 に下げた。レース中は BGM (0.4) とほぼ同じ大きさで、エンジンが BGM を覆い隠さない程度を目安にする
2. **高音を削る**: 耳障りさの主因は高い音 (エンジンのうなり、タイヤのキーという音)。走行系グループの出口にハイシェルフ (4 kHz 以上を -4 dB) とローパス (10 kHz) を入れる。タイヤのスキールは特に高音が強いので、スキール単体にも -3 dB のハイシェルフを追加する
3. **鳴りっぱなしにしない**: スキールは限界付近でだけ鳴り、グリップが戻ったら 0.15 秒でフェードアウトする。コース外の音は路面を離れたら 0.2 秒でフェードアウトする
4. **生成段階で柔らかい音を選ぶ**: 走行系 SE のプロンプトに `smooth, soft, not harsh, muffled high frequencies` を加え、ネガティブに `harsh, piercing, high-pitched whine, screeching feedback` を加える。候補の中から、波形のピークが鋭すぎないものを選ぶ

最終的な音量は試聴で決める。オプション画面の「効果音」音量の初期値は 0.8 とし、ユーザーがさらに下げられるようにする。
- 1 つの SE が短時間に連続再生される場合は、同じ SE の再発生間隔を最低 50 ms 空ける

## 5. 生成用プロンプトのテンプレート

### BGM (ACE-Step、英語のタグをカンマ区切り)

スクリプトが先頭に `instrumental, video game music,` を自動で付ける (歌なし固定)。

```
<共通タグ>, <曲ごとのタグ>, <テンポ> bpm
```

| 区分 | タグ |
| --- | --- |
| 共通 | `chiptune, synthwave, retro 16-bit, racing game, FM synth bass, arpeggio, electronic drums` |
| menu-theme | `mid tempo, 120 bpm, cool, night drive, anticipation, warm pads, catchy melody` |
| qualifying-theme | `130 bpm, tense, focused, minimal, driving bassline, light drums, clean mix` |
| race-theme | `fast tempo, 150 bpm, energetic, driving bassline, arpeggio, clean mix, light` (テスト生成のタグを基本にする) |
| result-theme | `105 bpm, triumphant, relaxed, bright melody, celebration` |
| ジングル | `short fanfare, victory jingle, bright, 4 seconds` (生成秒数を 6〜8 秒にし、変換時に切り出す) |

- 避けるタグ: `vocals, choir, singing, rap, spoken`, `orchestral, cinematic, epic`, `heavy metal, distorted guitar` (中低域が厚くなりエンジン音を隠す), `lofi` (レース中に遅く聞こえる), `ambient` (レース用)
- ACE-Step にネガティブプロンプトは無い (スクリプトで無効化している)。避けたい要素はタグに書かないことで避ける

### SE (Stable Audio Open、英語の自然文)

スクリプトが先頭に `sound effect, isolated, clean recording,` を付け、ネガティブに `music, melody, speech, voice, low quality, distorted, noise hiss` を自動で入れる。追加のネガティブは `--negative` で渡す。

```
<何の音か>, <どんな状態か>, <距離・質感>, <長さ>
```

| 区分 | 語句 |
| --- | --- |
| 共通で入れる | `close-up, dry, no reverb`、ワンショットは `single, short`、ループ素材は `steady, constant, continuous` |
| 走行系の例 | `formula racing car engine at constant mid rpm, high-pitched V10 scream, steady, no acceleration, close-up, dry` |
| 中継・UI 系の例 | `retro 8-bit video game menu cursor blip, short, clean square wave` |
| 追加のネガティブ (共通) | `reverb, echo, crowd, ambience, background noise, wind` (風切り音自体を作るときは wind を外す) |
| ループ素材の追加ネガティブ | `acceleration, revving, doppler, pass by, fade` (回転数やピッチが変わるとループにならない) |

- 避ける語句: `cinematic, movie, trailer` (残響やうなり音が付く)、`crowd, stadium` (歓声が混ざる)、実在の車名・チーム名・メーカー名
- 長さの目安: ワンショット 1〜3 秒、ループ素材 4〜6 秒 (中央を切り出す)

### 変換時の注意

- ループ化の条件: 変換スクリプトは「長さ > クロスフェード × 3」でないとループ化できない。既定のクロスフェードは 2 秒なので、**エンジンなど短いループは `--crossfade 0.3〜0.5` を指定**する
  - 例: `npm run gen:sound-convert -- --type se --loop --crossfade 0.4 --start 1 --end 4 --in <元音声> --out public/assets/sounds/se/engine-player-loop.ogg`
- SE は変換時に前後の無音が自動で除去される
- バリエーションは同じプロンプトの別 seed から選ぶ (音色が揃う)。採用した seed とプロンプトは sound-list.md に記録する

## 6. 再生側 (game-engineer) への要件まとめ

- Web Audio API で `decodeAudioData` した `AudioBuffer` を使い、ループは `AudioBufferSourceNode.loop = true` で再生する (`<audio loop>` はつなぎ目に隙間が出るため使わない)
- ブラウザの自動再生制限のため、`AudioContext` は最初のキー入力・クリックで `resume()` する (タイトル画面の「キーを押してください」で開始)
- ノード構成: `source → (ローパス) → gain → StereoPanner → グループ gain → コンプレッサー → master gain → destination`
- 再生速度・音量・パン・ローパスの変化は `setTargetAtTime` で滑らかに追従させる
- 同時発音数の制限: 他車エンジン最大 4 台 (近い順)、他車スキール最大 2 台、接触音最大 4 本
- 音はすべて各端末で車の状態から鳴らす。オンライン対戦でも音のためだけの通信は不要 (接触イベントは接触判定の同期結果から鳴らす)
- 画面が非表示 (タブ切り替え) のときは `AudioContext.suspend()` で止める
